# 阶段性审核

适用范围：审稿、质检、改写之前的诊断，以及决定要不要继续写后面的正文。

格式标记以 `references/script-format-spec.md` 和 `scripts/validate_script_format.py` 为准。本文件判断故事是否成立。合规边界仍以 `references/quality-and-boundaries.md` 为准。

## 先分级

- **结构性问题**：核心梗弱、主线错位、期待不成立、人物关系不产戏。先改框架，不先润色。
- **事件性问题**：事件没有因果、手段重复、阶段没有递进。重排阶段事件。
- **场景性问题**：对手戏没有状态变化、台词生硬、动机弱。改这场戏里的行动和对白。
- **语言性问题**：表达啰嗦、说明过多、语气不像这个人。最后处理。

审稿时把三类弱点分开：故事前提弱，某一集的事件弱，某一句台词弱。按严重程度排列。每条写清原文证据、造成的影响、修正方向。

用户只要求分析时，停在诊断，不直接改写。用户只要求改局部时，其余已经确定的人设、能力、关系、时间线、关键事件和结局保持不动。

## 前三集：验证方向

检查：核心梗够不够强，第 1 集四项任务有没有完成，人物关系是否产戏，情绪有没有真正起来，观众是否知道自己在等什么，是否至少有过一次和卖点一致的情绪回报。

第 1 集四项任务是：让观众停下来，让观众看懂，让观众产生情绪，向观众承诺后面会看到的具体内容。细则见 `references/methodology-opening.md`。

设定或主要关系不成立时，重做选题和大框。不要靠把剧情写长来救结构问题。这一关没过，就不继续生成大量后续集数。

## 第一阶段：验证框架

项目启用了一卡时，用一卡的标准。没有启用时，用第一阶段或用户指定的第一个重大节点。没有这样的节点，就不要虚构一集付费点再拿来挑错。

检查：主线是否集中，阶段大事件是否成立，信息差是否会改变行动，反复拉扯是否每一轮都有变化，节点是否把故事送进新阶段。

如果只是用同一个手段撑集数，就重新设计这一阶段的事件。必要时重做大纲。

## 中段：验证递进

项目启用了二卡时，用二卡的标准。没有启用时，检查中段本身。

检查：新矛盾是不是从前一段的结果里长出来的，有没有真正改变冲突机制或关系，主要期待是否仍然成立，后面能否兑现，而不是突然扔出一个终极设定。

中段递进的三类可用机制：新的整体危机或新的关键人物，有因果的更深层真相，一层层变化的情感拉扯。细则见 `references/methodology-cards.md`。互不相关的小麻烦不算递进。

## 终局：验证兑现

项目启用了三卡时，用三卡的标准。没有启用时，检查终局本身。

检查：已经做出的重要承诺有没有收回，最终的情绪回报够不够，有没有缺少铺垫的解决办法，有没有主要冲突已经结束后还在拖的尾声。

## 写进原有质检六段

质检输出保持原有六段，不用另一套标题替换：

- **一、格式问题**：标记、场景编号、人物行、交付载体。跑脚本能查出的问题写在这里。
- **二、节奏问题**：手段重复、小麻烦铺平、阶段没有递进、该停时还在堆集。
- **三、爽点问题**：核心期待模糊，爽点五个环节缺了哪一环，只有憋屈没有局部回报。五个环节是前置压迫或欲望、可预见的结果、有效行动、可见的局面或关系变化、后续后果。
- **四、钩子问题**：小卡点是不是假悬念。假悬念是只说“你想不到”或直接切黑，却没有写明即将发生的具体结果。项目如果有大卡点或一卡、二卡、三卡，再评主线状态有没有变。
- **五、可拍摄性问题**：场景有没有状态变化，行动能不能拍，台词能不能演。
- **六、修改建议**：按结构、事件、场景、语言的顺序给。

篇幅已经跨过一个阶段，或用户明确要看卡点、付费点、值不值得继续写时，在六段之后追加：

```text
七、阶段审核
已通过：
未通过：
是否继续写后续集数：
```

项目没有一卡、二卡、三卡时，第七段使用“开篇 / 第一阶段 / 中段 / 终局”，不编造付费集。

## 失败模式

| 失败模式 | 典型症状 | 修正方向 |
|---|---|---|
| 主线涣散 | 一集复仇，一集无关恋爱，一集另开一条副本 | 统一目标。支线必须带出主线后果 |
| 只堆情节 | 新角色、新场景不断出现，核心期待被冲淡 | 回到高情绪的那一个切面 |
| 只有手段加码 | 更大的帮手、更高的金额、更狠的责骂 | 更换对抗策略，改变利益、关系或风险 |
| 小麻烦堆积 | 多个小事件互不相关 | 收成一个清楚的大事件 |
| 无效信息差 | 角色只是一直不说出真相 | 让误判影响行动，并安排一次阶段性的揭晓 |
| 核心期待模糊 | 一直说后面有大事，但不告诉观众是什么 | 写明未来节点和要面对的风险 |
| 爽点没有落地 | 主角说了狠话，事情没有变化 | 补上前置压迫、有效行动和看得见的后果 |
| 只有憋屈 | 连续多集受辱，没有局部成果 | 安排阶段性的反击或关系改变 |
| 情感循环归零 | 反复误会之后，认知和信任毫无变化 | 每一轮更换证据、手段、代价和情感位置 |
| 人物降智 | 为了维持误会，忽略明明能用的信息和能力 | 把障碍改成真实的利益冲突或合理限制 |
| 节点之后失速 | 大卡点之后临时开启一个新故事 | 提前设计下一阶段的大事件和承接因果 |
| 中段没有递进 | 同一个对手不断制造杂事 | 改成新危机、更深层的因果，或一层层的关系拉扯 |
| 集尾假悬念 | “你猜怎么着”，然后黑屏 | 让观众知道即将出现的具体结果 |
| 反派没有动机 | 随意作恶，没有收益目标 | 写清资源、利益、行动逻辑和后果 |
| 先写后想 | 连续生成几十集之后才寻找主线 | 前三集和第一阶段没有通过，就不扩写 |

## 报告里要回答的问题

总评先回答三句：核心期待是否成立，主线是否集中，阶段是否递进。

然后按严重程度写结构性问题、事件性问题、人物问题、情绪问题、卡点问题。人物问题包括动机、已知信息、行动和关系变化前后不一致。卡点问题把小卡点、阶段大节点和用户真正提出的商业要求分开。

修订顺序固定为：结构，事件，场景，语言。

需要用户决定的分歧只列会改变方向的选择，例如主线从复仇改成和解。不把措辞偏好抛回给用户。

事实和推断分开。剧集内容和数据只使用已经拿到的材料。推测就标明是推测。不引用材料里没有的对话或隐藏上下文，也不把用户没有给出的外部结论当成事实。
