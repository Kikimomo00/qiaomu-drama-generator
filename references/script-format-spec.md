# 严格剧本标记规范

本规范来自用户提供的《荒年穿越短剧制作（完整）.docx》格式抽取。该文档只作为格式、标记和可拍摄写法参考，不限定题材、人物、世界观或剧情。生成任何风格的正文剧本时都优先遵守本规范；`.txt` 和 PDF 只是交付载体，内容标记保持一致。

## 顶层结构

完整正文剧本必须按以下顺序输出：

```text
项目名或文档标题
一、剧本
项目简介段落
二、正文剧本
剧名或剧名副标题
第 1 集
1-1 场景名 日内
人物：人物甲，人物乙
...
```

硬规则：

- 文档开头可写项目名或剧名；如果用户只要正文，也至少写《剧名》。
- 必须出现“一、剧本”和“二、正文剧本”，顺序不能反。
- “一、剧本”下面写项目简介，不写人物小传式堆料。
- “二、正文剧本”下面单独写一行剧名或剧名副标题。
- 正文按“第 N 集”分集，不用 Markdown 标题符号。

## 分集与场景

每集格式：

```text
第 1 集
1-1 村子茅草屋 日内
人物：徐小梅，张秀娥，徐长寿
屋内破旧。小梅、小梅妈趴在床边哭。床上躺着小男孩。
徐小梅（焦急）：三哥你醒醒呀。
△ 徐长寿睁开眼睛。
```

上方只是标记示例。实际创作时，应替换为当前题材需要的地点、人物和事件，例如公司后台、医院走廊、夜店门口、古镇戏台、豪门宴会厅、警局问询室等。

场景行规则：

- 使用阿拉伯数字：`N-M 场景名 时间内外`。
- `N` 必须等于当前集数，`M` 从 1 起递增。
- 时间标记优先使用：`日内`、`日外`、`夜内`、`夜外`、`昏内`、`昏外`。
- 地点字幕可并入场景行尾：`9-2 一座红木门大宅 日内【字幕：燕子巷柳府】`。
- 不要写成“场景一”“第一场”“室内/室外”等其他格式。

人物行规则：

- 每个场景行后必须紧跟或尽快出现 `人物：`。
- 人物之间用中文逗号 `，` 分隔。
- 只列本场实际出现或发声人物。
- 可在人物名后用括号补充识别，如 `柳洛灵 (红衣女)`。

## 行级标记

允许的正文行类型：

```text
动作描述
△ 关键动作描述
Δ 关键动作描述
人物名：对白。
人物名（状态）：对白。
人物名（OS）：内心独白。
人物名（VO）：旁白或未出镜声音。
系统（VO）：系统提示。
系统面板（字幕）：【面板内容】
兑换商城系统面板（字幕 + VO）：【面板内容】
【字幕：地点或信息】
【闪入】短暂画面描述。【闪入结束】
```

动作行：

- 可不加符号，直接写可拍摄动作。
- 重要动作、视觉变化、系统面板出现、道具落下等优先用 `△` 或 `Δ`。
- 不写抽象心理总结，例如“他感到命运不公”。改成动作、OS 或对白。

对白行：

- 使用中文冒号 `：`。
- 角色名必须在冒号前。
- 情绪、身份、OS、VO 写在中文括号内：`徐长寿（OS）：...`。
- 台词短、直、可演，避免一口气解释设定。

系统与字幕：

- 系统流必须出现系统面板行，且面板内容放在 `【】` 内；非系统题材不要硬塞系统面板。
- 价格、订单、地点、证据、身份、倒计时等可用字幕或系统面板展示。
- `【闪入】...【闪入结束】` 用于过去画面、想象画面、听闻画面。

## 文件交付

当用户要求输出文件：

- 默认生成 `.txt`，编码为 UTF-8。
- 用户明确要求 PDF 时再导出 PDF。
- PDF 不改变正文结构，不改成表格、PPT、散文或 Markdown 标题。
- `.txt` 和 PDF 内容都必须能看见“一、剧本 / 二、正文剧本 / 第 N 集 / N-M / 人物：”这些标记。

## 格式自检

交付前检查：

- 是否包含“一、剧本”和“二、正文剧本”。
- 是否至少有一个“第 N 集”。
- 是否每集有至少一个 `N-M` 场景。
- 是否每个场景附近都有 `人物：`。
- 是否出现对白行、动作行、OS/VO/字幕/系统面板中的必要类型。
- 系统流、重生流、商城流是否有系统面板或明确视觉化标记。
- 续写时场景编号是否从下一集继续，不重置、不跳乱。
