# 正文格式与输出模式

本文件给出通用输出模式；正文剧本的行级标记以 [严格剧本标记规范](script-format-spec.md) 为准。参考文档只约束格式写法，不约束题材和剧情。

## 完整剧本结构

当用户要求生成完整剧本，必须使用：

```text
《剧名》

一、剧本
[300-800 字项目简介]

二、正文剧本
剧名副标题或完整剧名

第 1 集
1-1 场景名 日内/日外/夜内/夜外
人物：人物甲，人物乙，人物丙
△ 动作
人物名（状态）：对白。
人物名（OS）：内心独白。
系统（VO）：系统提示。
系统面板（字幕）：【信息】

第 2 集
2-1 场景名 日内/日外/夜内/夜外
人物：...
...
```

必须符合：

- 先有“一、剧本”，再有“二、正文剧本”。
- “二、正文剧本”后必须再写一行剧名或剧名副标题。
- 每集写“第 N 集”。
- 每场写“N-M 地点 时间内外”。
- 每场必须有“人物：”。
- 动作可以是无标记动作行，也可以用“△”或“Δ”开头；关键动作、系统显现、重要视觉变化优先加动作标记。
- 对白用“人物名：台词”；带状态、OS、VO 时用“人物名（状态）：台词”“人物名（OS）：台词”“人物名（VO）：台词”。
- 可使用 OS、VO、字幕、系统面板、闪入。
- 不写小说式大段叙述。
- 每集结尾必须有钩子。
- 如用户要求 `.txt` 或 PDF 文件，文件内容仍必须保持这些标记，不得转成散文、表格或分镜表。

## “一、剧本”简介

简介包含：核心爽点线、主角初始处境、金手指或核心能力、第一阶段目标、中后期危机、终极方向。

推荐模板：

```text
《X》以“【主爽点线】”为核心线，满足观众对“【情绪期待】”的期待。
剧中主角【姓名】因【关键事件】陷入/来到【世界与处境】，成为【弱势身份】。此时【外部危机】，家中/事业/情感处境【极差】。
万幸的是，【主角】觉醒/拥有【金手指或能力】，他/她借助【能力优势】，通过【第一桶金/第一证据/第一反击】逐步摆脱困境。
随着【更大危机】浮现，【主角】开始【产业升级/关系反转/复仇布局/身份揭露】，并与【主要反派或关键关系】周旋对抗，最终立志【终极目标】。
```

## 场景与对白

场景编号示例：

```text
1-1 村子茅草屋 日内
1-2 茅草屋外 日外
2-1 集市 日外
```

人物行只列本场实际出现或发声人物，顺序按出场或戏份排序。

动作要可拍摄：

```text
△ 徐王氏一把夺过粮袋，米粒从袋口洒落。
△ 小梅扑到地上，捡起米粒往嘴里塞。
△ 徐长寿攥紧拳头，眼眶发红。
```

对白要短、直、狠、可演。避免长解释。

OS、VO、字幕、系统面板：

```text
徐长寿（OS）：这是……穿越了？
系统（VO）：检测到宿主情绪剧烈波动，兑换商城强制激活。
兑换商城系统面板（字幕）：【糙米 2 文钱 / 斤，每日限购 3 斤】
【字幕：燕子巷柳府】
【闪入】大户人家小姐吃蘑菇画面。【闪入结束】
```

## 输出模式

一句话生成：直接输出《剧名》、“一、剧本”和“二、正文剧本”。默认 20 集；篇幅受限时先给前 5-10 集正文，并让结构可续写。

先给大纲：输出《剧名》、“一、核心设定 / 二、人物关系 / 三、金手指或能力规则 / 四、反派阶梯 / 五、分集大纲”。每集大纲含剧情、爽点、钩子。

续写：直接从下一集开始，不重复长总结。保持人名、关系、金手指规则、金钱数字、道具来源、反派动机、台词风格和场景格式一致。

文件交付：默认交付 UTF-8 `.txt`。只有用户明确要求“PDF、打印版、成稿文件”时才导出 PDF；PDF 只是载体，正文标记必须与 `.txt` 一致。

优化/改写：用户要求直接改时，直接输出优化版；否则输出“一、主要问题 / 二、优化策略 / 三、优化后版本”。

检查：输出“一、格式问题 / 二、节奏问题 / 三、爽点问题 / 四、钩子问题 / 五、可拍摄性问题 / 六、修改建议”。

## 结尾钩子库

身份钩子：大小姐车已备好、集团新任董事长曝光、旧部跪拜、真实身份只露一角。

资源钩子：隐藏商品解锁、掌柜要独家、后台订单暴涨、新任务倒计时。

危险钩子：反派听到计划、官差/保安/记者冲进来、孩子不见、证据被抢。

真相钩子：亲子鉴定递到手里、监控里出现真凶、医生说当年救你的人不是她。

情感钩子：病历被看见、前夫跪求、孩子挽留、男主公开偏爱。

商业钩子：竞品挂出同款招牌、贵人要求独家、秘方泄露、发布会临时出事。

法律/舆论钩子：大屏播放录音、律师推门、直播间弹幕炸裂、合同无效。
